# 提示词设计

## 目标

把「截图 → 新增英文段落 → 中文译文」这件事做稳，需要同时解决四件事：只翻新内容、顺序稳定、公式不被翻译、输出可解析。

## 系统提示词（内置，可被用户整段替换）

```
你是英文学术论文（强化学习 / 机器人方向）的翻译引擎。
你只输出 JSON，绝不输出分析、计划或解释。
```

短，且是命令式。长提示词会诱发模型写「分析」。

## 用户提示要点

1. **输出契约**：`{"segments":[{"i":1,"en":"…","zh":"…"}]}`；
2. **段序**：`i` 从 1 开始连续递增，必须对应截图从上到下的顺序，最上面那段正文就是 `i=1`，不许跳段；
3. **数量**：这一屏有多少段就输出多少段（通常 20–40 条），宁可拆细也别漏；
4. **已知清单**：附上「已翻译（不要重复）」的最近 26 条英文；
5. **不可翻内容**：公式、变量名、算法名（PPO/SAC/MuJoCo）、引用标记保持原样；译文里不要出现 `$` 或 `\` 开头的 LaTeX 标记；
6. **边缘残缺**：截图边缘可能截到半行字，按能读到的内容照常翻，不要跳过整段；
7. **框选模式**：一共两张图，第一张是选区（只翻它），第二张是整屏（只作上下文）。

## 踩过的坑

### 1. 模型把「思考过程」当正文输出

DeepSeek 的 `deepseek-flash` **默认开启思考模式**，思维链写在 `reasoning_content`，`content` 可能为空。表现是浮窗里出现「We need output only JSON…」「让我逐句分析…」这类文字。

解决：请求里显式关闭——

```json
{"thinking": {"type": "disabled"}}
```

（想更准时打开：`{"thinking": {"type": "enabled"}}` + `max_tokens` 提到 8K。）

### 2. 输出被截断导致整批丢失

`max_tokens` 不够时 JSON 从中间断掉，整体解析失败。两层兜底：

- 输出上限提到 16K；
- 解析失败时用正则从半截 JSON 里捞出已闭合的 `{en,zh}` 对（`Translator.salvage`）。

### 3. 顺序抖动

模型每次选择从哪段开始不一样。要求每段带 `i` 并在客户端按 `i` 排序后显示；同时提示词写死「最上面那段必须是 i=1，不许跳段」。

### 4. 只翻一部分

提示词里曾写「最多 12 条」，结果每屏只翻 12 段。改成「有多少段翻多少段」并放宽上限。

## 术语表

内置约 60 个 RL/机器人高频词（policy 策略、advantage 优势、sim-to-real 仿真到现实…），用户可以在 App 里追加自己的术语，追加部分会以「额外术语（必须优先遵守）」的形式拼接，优先级高于内置。
